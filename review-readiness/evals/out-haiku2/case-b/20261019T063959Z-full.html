D1 Dedupe logic inserts wrong event identifier, defeating duplicate detection entirely.

Where src/webhooks/refundHandler.ts:26

Failure scenario Event evt_1 arrives twice from Stripe: (1) first call checks event.id='evt_1' (not in table), inserts refund.id='re_1', applies refund; (2) second call checks event.id='evt_1' (not found—we stored 're_1'), applies refund again. Customer balance credited twice, defeating the PR's core purpose.

Evidence src/webhooks/refundHandler.ts:18 checks db.processedEvents.findOne({ eventId: event.id }) (correct: Stripe event ID 'evt_1'), but line 26 inserts { eventId: refund.id } (wrong: refund ID 're_1'). Redelivered events with same event.id will not be found because the inserted eventId is different. CONFIRMED by code inspection.

Fix Change line 26 from await tx.processedEvents.insert({ eventId: refund.id, ...}) to await tx.processedEvents.insert({ eventId: event.id, ...})
